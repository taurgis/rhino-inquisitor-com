# SEO audit — July 2026 (deep pass)

**Date:** 2026-07-02
**Scope:** Independent, deep technical + content + performance SEO audit of the live apex
site (`https://rhino-inquisitor.com/`), verifying the same-day launch audit
([launch-audit-fixes.md](launch-audit-fixes.md)) held live and going deeper across article,
taxonomy, and paginated routes plus all 151 posts.

## Change summary

The site was already in excellent shape — canonicals, pagination, 404s, structured data,
sitemap index, RSS/llms, host consistency, and zero-tracker/near-zero-JS delivery all
verified clean. This pass fixed a focused set of real defects and one live regression.

## Why this changed

Three defects were live-affecting (stale critical CSS causing CLS; missing article OG
freshness signals; over-long `<title>` tags truncating in SERPs) and several were latent
process/regression risks (no CI enforcement of critical-CSS freshness; www/apex doc drift
that could steer a future contributor to reintroduce mixed-host links; AVIF tier gap).

## Behavior details (old → new)

### 1. Over-long `<title>` tags (91/151 posts) — `seo/resolve.html`
- **Old:** every non-home page composed `"<title> | Rhino Inquisitor"`; the 19-char suffix
  pushed 91 posts past Google's ~60-char SERP limit.
- **New:** if the composed title exceeds 60 chars, the ` | Rhino Inquisitor` suffix is
  dropped and the page uses the bare title. Short titles keep the suffix.
- **Residual:** a few posts whose front-matter title *alone* exceeds 60 chars still truncate;
  these are an optional future editorial pass (shorten the source `title`), not a template bug.

### 2. Missing article Open Graph freshness/completeness — `seo/open-graph.html`
- **Old:** posts set `og:type=article` but emitted no `article:*` tags; no `og:site_name`,
  `og:locale`, or `og:image:alt`.
- **New:** posts emit `article:published_time`, `article:modified_time` (ISO-8601, matching the
  JSON-LD dates), `article:author`, `article:section` (per category), `article:tag` (per tag).
  All pages now emit `og:site_name`, `og:locale=en_US`, `og:image:alt`, and `twitter:image:alt`.

### 3. JSON-LD article author enrichment — `seo/json-ld-article.html`
- **Old:** `author` was a bare `Person` with only `name`.
- **New:** adds `url` (→ `/about/`) and `sameAs` (GitHub + LinkedIn), aligning with the
  Organization node's profiles. All article JSON-LD blocks still parse.

### 4. Critical CSS drift — live CLS regression + no CI enforcement
- **Old:** committed `src/assets/styles/critical-*.css` had drifted from `site.css` again
  (site-brand logo rule `height:1.875rem` vs actual `width:auto;flex:none;object-fit:contain`;
  archive footer rules no longer above-the-fold). The live site was serving the stale inlined
  CSS — a real above-the-fold layout-shift source. Regeneration was a manual, unenforced step.
- **New:** regenerated the three critical files, AND added a CI gate to `build-pr.yml`
  ("Check critical CSS is in sync") that re-runs `npm run generate:critical-css` and fails the
  build on any diff in `critical-*.css`. Generator output is deterministic within an
  environment (two consecutive runs byte-identical).
- **Caveat:** cross-environment (macOS↔Linux) determinism is unverified. If the first CI run
  flags spurious drift, commit the CI-generated baseline.

### 5. Lighthouse coverage — `lighthouserc.json`
- **Old:** collected `/`, one article, and `/category/ai/` — never `/posts/` (the primary
  archive route).
- **New:** `/posts/` added to the collect list at the same 0.9 threshold.

### 6. AVIF srcset tier gap — `scripts/generate-avif-cache.js`
- **Old:** generator produced only `[768, 1280]` widths; templates request `[480, 768, 960]`
  (render-image / img-caption), so AVIF `<source>` srcsets were missing 480w/960w while WebP
  had them — capable browsers upscaled 768w AVIF.
- **New:** generator produces `[480, 768, 960, 1280]`. Verified: article images now expose
  matching AVIF/WebP width tiers (smaller-source images correctly cap without upscaling).

### 7. Category term descriptions — `seo/resolve.html` + `src/data/categoryDescriptions.toml`
- **Old:** all category pages shared a templated "…articles about X and related Salesforce
  Commerce Cloud guidance." string.
- **New:** hand-written per-term descriptions keyed by term slug, with the generic template as
  fallback for unmapped terms.

### 8. www→apex documentation drift (pervasive)
- **Old:** `seo-compliance.instructions.md` + generated mirror, `hugo-coding-standards` generated
  mirror (canonical-override line), and BOTH `hugo-development` and `seo` SKILL.md files still
  stated `www` as the canonical host — contradicting live behavior and `hugo.toml` (apex; www
  301s to apex). A contributor following them literally would reintroduce mixed-host links.
- **New:** all corrected to apex. SKILL.md edits followed the `skill-authoring` skill per repo
  governance.

## Hand-off (Cloudflare / infra — out of repo)

1. **`http://www` → 2-hop redirect:** `http://www.rhino-inquisitor.com/` currently does
   http+www → http apex → https apex. Add a Cloudflare Redirect Rule collapsing it to a single
   301 to `https://rhino-inquisitor.com/`.
2. **Fingerprinted asset cache TTL:** assets serve `Cache-Control: max-age=2678400` (31d);
   set `max-age=31536000, immutable` for `/styles/*`, `/fonts/*`, `/generated-avif/*`,
   `/images/*` via a Cloudflare Cache/Transform Rule.

## Impact

- **Users/search:** better SERP titles, richer social/article previews, no archive CLS, tighter
  image bytes on AVIF clients.
- **Maintainers:** critical-CSS drift now fails CI instead of silently shipping; SEO/Hugo docs
  no longer contradict the live canonical host.

## Verification

- `npm run build:prod` — 0 errors; `npm run check:url-parity` — 1224/1224, 0 blocking failures;
  `npm run check:seo` — passed for 223 indexable routes.
- Built-output spot checks: long-title post drops suffix; short-title keeps it; `article:*` +
  `og:site_name`/`og:image:alt` present and dates match JSON-LD; `/category/ai/` shows the
  hand-written description; AVIF/WebP width tiers match; all article JSON-LD parses.
- Critical-CSS gate dry-run: reproduced the drift, confirmed regeneration is deterministic
  within-env.
