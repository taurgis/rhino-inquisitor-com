# OCAPI Metadata

The Open Commerce API provides data about itself (metadata). You can obtain API metadata by accessing an own API, the *meta* API.

- [A list of available APIs]
- [A list of available versions for an API]
- [A list of resources and their descriptions]
- [A list of accessible documents]
- [A description for a single document]

To access the Meta API, you have to send an *Authorization: Bearer* [OAuth token] with every request, which is obtained via Account Manager. With the client ID, used to create the access token, the access to all resources via OCAPI settings is proofed and only the available resources and documents are shown. The same applies to accessing the metadata in a global context, where the global OCAPI settings are used to retrieve only the metadata the client is allowed to access.

The Meta API responses are cached in the page cache for 24 hours.

## Detailed

# OCAPI Metadata

The Open Commerce API provides data about itself (metadata). You can obtain API metadata by accessing an own API, the *meta* API. This API can be accessed like the shop and the data API, but with version 1 as API version. The meta API provides information about

- [A list of available APIs](/docs/commerce/b2c-commerce/references/b2c-commerce-ocapi/metadata.html#list-of-apis)
- [A list of available versions for an API](/docs/commerce/b2c-commerce/references/b2c-commerce-ocapi/metadata.html#list-of-versions)
- [A list of resources and their descriptions](/docs/commerce/b2c-commerce/references/b2c-commerce-ocapi/metadata.html#list-of-resource-descriptions)
- [A list of accessible documents](/docs/commerce/b2c-commerce/references/b2c-commerce-ocapi/metadata.html#list-of-documents)
- [A description for a single document](/docs/commerce/b2c-commerce/references/b2c-commerce-ocapi/metadata.html#show-document-information)

To access the Meta API, you have to send an *Authorization: Bearer* [OAuth token](/docs/commerce/b2c-commerce/references/b2c-commerce-ocapi/oauth.html) with every request, which is obtained via Account Manager. With the client ID, used to create the access token, the access to all resources via OCAPI settings is proofed and only the available resources and documents are shown. The results may differ, depending on the context used to access the metadata. In the context of a specific site, the OCAPI settings of the site are used to check the access rights for the requesting client and show him only the resources he’s allowed to access. The same applies to accessing the metadata in a global context, where the global OCAPI settings are used to retrieve only the metadata the client is allowed to access.

The Meta API responses are cached in the page cache for 24 hours. This means that the cache for the metadata is automatically cleared with page cache clearing.
