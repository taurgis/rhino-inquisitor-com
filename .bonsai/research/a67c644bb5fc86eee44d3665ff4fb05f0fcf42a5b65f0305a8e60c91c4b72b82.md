# Create Storefront Next in Business Manager with Local Code

Create a storefront and its dependent API and Managed Runtime (MRT) resources in Business Manager with the local CLI option to generate and store your code locally.

## Prerequisites

- A developer B2C Commerce instance or on-demand sandbox (ODS) instance. See [Create On-Demand Sandboxes for B2C Commerce] in *Salesforce Help*.
- Managed Runtime User or Managed Runtime Admin role in Account Manager.
- Business Administrator role in Account Manager or a role for the Business Manager Module and Organization context with read-write access to storefronts. See [Create a Role in B2C Commerce] in *Salesforce Help*.
- The prerequisites for creating storefront code with the CLI. See the prerequisites in [Explore Storefront Next Code Locally].
- A B2C Commerce site associated with a catalog, price book, and an inventory. See [Create and Manage Sites for Development] and [Merchandising Your Site in B2C Commerce] in *Salesforce Help*.

## Constraints

- Storefront setup supports only one storefront per site. A site can't be associated with more than one storefront.
- If storefront setup fails, you must delete and recreate the storefront.

## Steps

1. In Business Manager, click App Launcher  and then select **Administration > Sites > Storefronts > New Storefront**.

2. Select the template that's suitable for your storefront's merchandise. The built-in templates provide the layout, theme, and style that are customized for the products to sell, and product attributes specific to an industry. To check the layout of a template on a demo site, click **View Demo**. To select a template to build your storefront with, click **Use Template**.

   

   a. Select the Market Street template for personal and household goods, including clothing, shoes, electronics, and so on. See the [Market Street demo site].

   b. Select the Beauty Street template for beauty and cosmetic products. See the [Beauty Street demo site].

3. Enter the storefront name. For example, `my-local-storefront`.

4. Select a site. You can select one or more sites for your storefront. For this task, select one site.

   :::important
   You can assign a site to one storefront only. You can't reuse it for another storefront.
   :::

5. Select **Salesforce CLI** to generate the storefront code manually.

   

6. Click **Start Setup**.

7. After setup completes, in Source Code, click **Download .env** from the completion page to download the `env.txt` environment file. It contains your storefront's configuration, Business Manager settings, and your Account Manager and Shopper Login and API Access Service (SLAS) credentials.

   

   :::note
   For your security, the client secrets are available for download only once and are deleted on subsequent downloads. You use the Account Manager and SLAS client credentials to run the storefront locally. When you run the storefront on MRT, MRT uses the autocreated environment variables.
   :::

8. To view the storefront on MRT, click the view icon next to the environment.
   

9. To view details about the autocreated environment, in the Environments section, click the environment name. The new environment links to deployments, environment variables on MRT, and shows the eCDN routing rules for the default domain.

   Setup created an MRT project and sent an initial deployment of the storefront. The deployed bundle is a generated storefront that mirrors the storefront you generate with the CLI.

10. To view the deployment on MRT, from the storefront page in Business Manager, click **Manage** in the Deployments section. Verify that the setup process created an MRT project and environment and sent an initial deployment of the storefront app. To view the deployment on MRT, click **Managed Runtime Environment**.

    

11. To generate the storefront code, type this command in a terminal window.

    ```
    pnpm dlx @salesforce/storefront-next-dev create-storefront
    ```

    a. Provide the same storefront name you used earlier. For example, `my-local-storefront`.

    The storefront corresponds to a project in MRT. The autogenerated project ID, which is based on the storefront name, identifies your project in MRT. You set the project ID in a later step from the downloaded environment file.

    b. Select the same Storefront Next UI template you chose earlier.

    c. For the extensions, press Enter to accept the selected extensions.

    d. Accept the defaults for the client IDs and the B2C Commerce instance values.
    You overwrite the configuration with your own storefront environment file in the next steps.

12. Open the project folder in an IDE, and then open the environment file: `{project-folder}/.env`.

13. Replace the contents of `{project-folder}/.env` with the contents of the downloaded `env.txt` file, which contains values specific to the new storefront and the B2C Commerce instance.

    :::note
    The MRT project has a name and an ID, which are different. The `env.txt` file contains the MRT project ID.
    :::

14. Make sure that your site's search indexes are up-to-date. For more information, see [Generate Search Indexes] in *Salesforce Help*.

15. In a terminal window, go to the storefront folder.

    ```
    cd {project-folder}
    ```

16. Install Storefront Next project dependencies that are specified in `package.json`.

    ```
    pnpm install
    ```

17. Build the storefront.

    ```
    pnpm run build
    ```

18. Run the development server.

    ```
    pnpm run dev
    ```

19. Open the development server URL shown in the output to view the storefront in the browser. For example, the URL with the default port is `http://localhost:5173`.

## Next Steps

- To add or modify Page Designer pages and components, deploy Page Designer metadata. See [Deploy the Storefront Next Cartridge for Page Designer]. This step isn't required when you set up a storefront by using GitHub.
- To deploy your storefront to MRT after making changes to it after the initial deployment, see [Deploy Storefront Next to Managed Runtime (MRT)].
- To change site assignments for the storefront, see [Manage Sites for Storefront Next in Business Manager].
- If you set up this storefront on an on-demand sandbox (ODS) instance, Business Manager automatically adds default security rules to the instance's default eCDN zone. These rules apply to every storefront hosted on that instance. See [Default Security Rules on On-Demand Sandbox (ODS) Instances].
- To link your storefront to a GitHub organization, see [Link Your Storefront to a GitHub Repository in Business Manager].
