## Compressed

### [1.2.] [Overview of the SVCB RR]

This subsection briefly describes the SVCB RR with forward references to the full exposition of each component.

The SVCB RR has two modes: 1) AliasMode ([Section 2.4.2]), which aliases a name to another name and 2) ServiceMode ([Section 2.4.3]), which provides connection information bound to a service endpoint domain.

The SVCB RR has two required fields and one optional field.

SvcPriority ([Section 2.4.1]):

The priority of this record (relative to others, with lower values preferred).

TargetName:

The domain name of either the alias target (for AliasMode) or the alternative endpoint (for ServiceMode).[¶]

SvcParams (optional):

A list of key=value pairs describing the alternative endpoint at TargetName (only used in ServiceMode and otherwise ignored).

Cooperating DNS recursive resolvers will perform subsequent record resolution (for SVCB, A, and AAAA records) and return them in the Additional section of the response ([Section 4.2]).

In ServiceMode, the SvcParams of the SVCB RR provide an extensible data model for describing alternative endpoints that are authoritative for a service, along with parameters associated with each of these alternative endpoints ([Section 7]).[¶]

For HTTP use cases, the HTTPS RR ([Section 9]) enables many of the benefits of Alt-Svc \[[AltSvc]\] without waiting for a full HTTP connection initiation (multiple round trips) before learning of the preferred alternative, and without necessarily revealing the user's intended destination to all entities along the network path.[¶]

## Detailed

### [1.2.](https://www.rfc-editor.org/info/rfc9460/#section-1.2) [Overview of the SVCB RR](https://www.rfc-editor.org/info/rfc9460/#name-overview-of-the-svcb-rr)

This subsection briefly describes the SVCB RR with forward references to the full exposition of each component. (As discussed in [Section 6](https://www.rfc-editor.org/info/rfc9460/#svcb-compatible), this all applies equally to the HTTPS RR, which shares the same encoding, format, and high-level semantics.)[¶](https://www.rfc-editor.org/info/rfc9460/#section-1.2-1)

The SVCB RR has two modes: 1) AliasMode ([Section 2.4.2](https://www.rfc-editor.org/info/rfc9460/#alias-mode)), which aliases a name to another name and 2) ServiceMode ([Section 2.4.3](https://www.rfc-editor.org/info/rfc9460/#service-mode)), which provides connection information bound to a service endpoint domain. Placing both forms in a single RR type allows clients to fetch the relevant information with a single query ([Section 2.3](https://www.rfc-editor.org/info/rfc9460/#svcb-names)).[¶](https://www.rfc-editor.org/info/rfc9460/#section-1.2-2)

The SVCB RR has two required fields and one optional field. The fields are:[¶](https://www.rfc-editor.org/info/rfc9460/#section-1.2-3)

SvcPriority ([Section 2.4.1](https://www.rfc-editor.org/info/rfc9460/#pri)):

The priority of this record (relative to others, with lower values preferred). A value of 0 indicates AliasMode.[¶](https://www.rfc-editor.org/info/rfc9460/#section-1.2-4.2)

TargetName:

The domain name of either the alias target (for AliasMode) or the alternative endpoint (for ServiceMode).[¶](https://www.rfc-editor.org/info/rfc9460/#section-1.2-4.4)

SvcParams (optional):

A list of key=value pairs describing the alternative endpoint at TargetName (only used in ServiceMode and otherwise ignored). SvcParams are described in [Section 2.1](https://www.rfc-editor.org/info/rfc9460/#presentation).[¶](https://www.rfc-editor.org/info/rfc9460/#section-1.2-4.6)

Cooperating DNS recursive resolvers will perform subsequent record resolution (for SVCB, A, and AAAA records) and return them in the Additional section of the response ([Section 4.2](https://www.rfc-editor.org/info/rfc9460/#recursive-behavior)). Clients either use responses included in the Additional section returned by the recursive resolver or perform necessary SVCB, A, and AAAA record resolutions ([Section 3](https://www.rfc-editor.org/info/rfc9460/#client-behavior)). DNS authoritative servers can attach in-bailiwick SVCB, A, AAAA, and CNAME records in the Additional section to responses for a SVCB query ([Section 4.1](https://www.rfc-editor.org/info/rfc9460/#authoritative-behavior)).[¶](https://www.rfc-editor.org/info/rfc9460/#section-1.2-5)

In ServiceMode, the SvcParams of the SVCB RR provide an extensible data model for describing alternative endpoints that are authoritative for a service, along with parameters associated with each of these alternative endpoints ([Section 7](https://www.rfc-editor.org/info/rfc9460/#keys)).[¶](https://www.rfc-editor.org/info/rfc9460/#section-1.2-6)

For HTTP use cases, the HTTPS RR ([Section 9](https://www.rfc-editor.org/info/rfc9460/#https)) enables many of the benefits of Alt-Svc \[[AltSvc](https://www.rfc-editor.org/info/rfc9460/#RFC7838)\] without waiting for a full HTTP connection initiation (multiple round trips) before learning of the preferred alternative, and without necessarily revealing the user's intended destination to all entities along the network path.[¶](https://www.rfc-editor.org/info/rfc9460/#section-1.2-7)
