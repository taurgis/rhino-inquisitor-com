2\. The SVCB Record Type > 2.1. Zone-File Presentation Format

## Compressed

### [2.1.] [Zone-File Presentation Format]

The presentation format `<RDATA>` of the record (\[[RFC1035]\], [Section 5.1]) has the form:[¶]

The SVCB record is defined specifically within the Internet ("IN") Class (\[[RFC1035]\], [Section 3.2.4]).[¶]

SvcPriority is a number in the range 0-65535, TargetName is a `<domain-name>` (\[[RFC1035]\], [Section 5.1]), and the SvcParams are a whitespace\-separated list with each SvcParam consisting of a SvcParamKey\=SvcParamValue pair or a standalone SvcParamKey.

Each SvcParamKey SHALL appear at most once in the SvcParams.

The SvcParamValue is parsed using the character\-string decoding algorithm ([Appendix A]), producing a `value`.

When the optional "=" and SvcParamValue are omitted, the `value` is interpreted as empty.[¶]

Arbitrary keys can be represented using the unknown-key presentation format "keyNNNNN" where NNNNN is the numeric value of the key type without leading zeros.

For some SvcParamKeys, the `value` corresponds to a list or set of items.

SvcParams in presentation format MAY appear in any order, but keys MUST NOT be repeated.[¶]

## Detailed

### [2.1.](https://www.rfc-editor.org/info/rfc9460/#section-2.1) [Zone-File Presentation Format](https://www.rfc-editor.org/info/rfc9460/#name-zone-file-presentation-form)

The presentation format `<RDATA>` of the record (\[[RFC1035](https://www.rfc-editor.org/info/rfc9460/#RFC1035)\], [Section 5.1](https://rfc-editor.org/rfc/rfc1035#section-5.1)) has the form:[¶](https://www.rfc-editor.org/info/rfc9460/#section-2.1-1)

The SVCB record is defined specifically within the Internet ("IN") Class (\[[RFC1035](https://www.rfc-editor.org/info/rfc9460/#RFC1035)\], [Section 3.2.4](https://rfc-editor.org/rfc/rfc1035#section-3.2.4)).[¶](https://www.rfc-editor.org/info/rfc9460/#section-2.1-3)

SvcPriority is a number in the range 0-65535, TargetName is a `<domain-name>` (\[[RFC1035](https://www.rfc-editor.org/info/rfc9460/#RFC1035)\], [Section 5.1](https://rfc-editor.org/rfc/rfc1035#section-5.1)), and the SvcParams are a whitespace\-separated list with each SvcParam consisting of a SvcParamKey\=SvcParamValue pair or a standalone SvcParamKey. SvcParamKeys are registered by IANA ([Section 14.3](https://www.rfc-editor.org/info/rfc9460/#svcparamregistry)).[¶](https://www.rfc-editor.org/info/rfc9460/#section-2.1-4)

Each SvcParamKey SHALL appear at most once in the SvcParams. In presentation format, SvcParamKeys are lowercase alphanumeric strings. Key names contain 1-63 characters from the ranges "a"-"z", "0"-"9", and "-". In ABNF \[[RFC5234](https://www.rfc-editor.org/info/rfc9460/#RFC5234)\],[¶](https://www.rfc-editor.org/info/rfc9460/#section-2.1-5)

The SvcParamValue is parsed using the character\-string decoding algorithm ([Appendix A](https://www.rfc-editor.org/info/rfc9460/#decoding)), producing a `value`. The `value` is then validated and converted into wire format in a manner specific to each key.[¶](https://www.rfc-editor.org/info/rfc9460/#section-2.1-7)

When the optional "=" and SvcParamValue are omitted, the `value` is interpreted as empty.[¶](https://www.rfc-editor.org/info/rfc9460/#section-2.1-8)

Arbitrary keys can be represented using the unknown-key presentation format "keyNNNNN" where NNNNN is the numeric value of the key type without leading zeros. A SvcParam in this form SHALL be parsed as specified above, and the decoded `value` SHALL be used as its wire-format encoding.[¶](https://www.rfc-editor.org/info/rfc9460/#section-2.1-9)

For some SvcParamKeys, the `value` corresponds to a list or set of items. Presentation formats for such keys SHOULD use a comma-separated list ([Appendix A.1](https://www.rfc-editor.org/info/rfc9460/#value-list)).[¶](https://www.rfc-editor.org/info/rfc9460/#section-2.1-10)

SvcParams in presentation format MAY appear in any order, but keys MUST NOT be repeated.[¶](https://www.rfc-editor.org/info/rfc9460/#section-2.1-11)
