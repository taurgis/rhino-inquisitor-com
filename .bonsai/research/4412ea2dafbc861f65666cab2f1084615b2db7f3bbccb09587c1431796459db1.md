### Tool annotations (optional)

When registering a tool, you can add metadata hints in the `annotations` property.

*   **`readOnlyHint`** (boolean, defaults to `false`): When `true`, indicates that the tool only reads information and does not modify the state of the application or system (for example, searching a product catalog or retrieving order status). This helps agents determine whether the tool can be safely called without side effects.
*   **`untrustedContentHint`** (boolean, defaults to `false`): When `true`, indicates that the tool's output contains untrusted data from the perspective of the tool author (for example, user-generated content, reviews, or external web data). This signals to the agent and client that the returned payload requires heightened security handling, such as sanitization or delimiting, to mitigate [indirect prompt injection].
*   **`consequentialHint`** (boolean, defaults to `false`): When `true`, indicates that executing the tool results in significant, real-world, or non-reversible actions (for example, booking a flight, transferring money, or deleting data). This allows agents and browsers to enforce mandatory user confirmation prompts before executing high-stakes tools, mitigating the risk of accidental or malicious misrepresentation of user intent.

### Handle tool cancellation

The `execute` function receives an `AbortSignal` parameter named `signal` as its second argument to gracefully handle execution cancellations initiated by the user or agent.

Use `document.modelContext.getTools()` to retrieve available tools.

By default, `getTools()` returns only same-origin tools registered by the calling document or other same-origin documents in the frame tree. To retrieve cross-origin tools, you must explicitly list their origins in the `fromOrigins` option.

Tools from cross-origin documents are only included if:

1.  The hosting origin is listed in the `fromOrigins` option.
2.  The tool has been explicitly [exposed to your origin].

See the [WebMCP Page Agent demo] for an example of how to retrieve tools from an iframe and execute them within a web-based chat interface.

To manually execute a tool discovered in `getTools()`, call `document.modelContext.executeTool()` with an optional JavaScript object for input arguments that is serializable to a JSON string.

You can cancel a pending tool execution with `AbortSignal`, when passed as an optional parameter.

You can use the WebMCP Imperative API to define many types of tools with standard JavaScript. Your tools can execute different functions, such as form input, site navigation, and state management.

Before using this API, read about [example use cases](https://developer.chrome.com/docs/ai/webmcp).

Use `registerTool` to add a single tool to the model context.

### Tool annotations (optional)

When registering a tool, you can add metadata hints in the `annotations` property. These hints help agents and browsers understand a tool's safety characteristics, expected side effects, and output trustworthiness:

*   **`readOnlyHint`** (boolean, defaults to `false`): When `true`, indicates that the tool only reads information and does not modify the state of the application or system (for example, searching a product catalog or retrieving order status). This helps agents determine whether the tool can be safely called without side effects.
*   **`untrustedContentHint`** (boolean, defaults to `false`): When `true`, indicates that the tool's output contains untrusted data from the perspective of the tool author (for example, user-generated content, reviews, or external web data). This signals to the agent and client that the returned payload requires heightened security handling, such as sanitization or delimiting, to mitigate [indirect prompt injection](https://developer.chrome.com/docs/ai/webmcp/secure-tools).
*   **`consequentialHint`** (boolean, defaults to `false`): When `true`, indicates that executing the tool results in significant, real-world, or non-reversible actions (for example, booking a flight, transferring money, or deleting data). This allows agents and browsers to enforce mandatory user confirmation prompts before executing high-stakes tools, mitigating the risk of accidental or malicious misrepresentation of user intent.

### Unregister tools

You can remove a tool with `AbortSignal`, when passed as an optional parameter.

As of Chrome 153, you can unregister a tool without cancelling and breaking in-flight executions. This prevents unexpected side effects when managing tool lifecycles in component frameworks.

### Handle tool cancellation

The `execute` function receives an `AbortSignal` parameter named `signal` as its second argument to gracefully handle execution cancellations initiated by the user or agent. Passing this signal to long-running asynchronous tasks or network operations (such as `fetch()`) helps prevent unnecessary work, improves overall resource management, and avoids potential leaks.

Use `document.modelContext.getTools()` to retrieve available tools. This asynchronous method returns an alphabetically ordered list of tools that the calling document is authorized to access.

By default, `getTools()` returns only same-origin tools registered by the calling document or other same-origin documents in the frame tree. To retrieve cross-origin tools, you must explicitly list their origins in the `fromOrigins` option. This array only supports secure origins.

Tools from cross-origin documents are only included if:

1.  The hosting origin is listed in the `fromOrigins` option.
2.  The tool has been explicitly [exposed to your origin](https://developer.chrome.com/docs/ai/webmcp/imperative-api?hl=en#origin-exposure).

See the [WebMCP Page Agent demo](https://github.com/GoogleChromeLabs/webmcp-tools/tree/main/demos/page-agent) for an example of how to retrieve tools from an iframe and execute them within a web-based chat interface.

To manually execute a tool discovered in `getTools()`, call `document.modelContext.executeTool()` with an optional JavaScript object for input arguments that is serializable to a JSON string. This asynchronous method returns the result of the tool execution, or null when a navigation is triggered.

You can cancel a pending tool execution with `AbortSignal`, when passed as an optional parameter.

## Events

Frames can listen for the `toolchange` event on `document.modelContext` to be notified when the list of available tools has changed.

## Cross-origin iframes

WebMCP supports cross-origin iframes that use both permission policies and explicit origin gating.

### Permissions policy

Tool registration is disabled by default in cross-origin iframes. A page must delegate access using the `tools` [Permissions Policy](https://developer.chrome.com/docs/privacy-security/permissions-policy):

### Origin exposure

Tools are unavailable to cross-origin documents by default. You can use the `exposedTo` array within `registerTool` to list specific origins allowed to view and execute a tool. This array only supports secure origins.

## React support

React has [experimental support for WebMCP](https://www.npmjs.com/package/usewebmcp) using the `usewebmcp` package. If your application is already written with React, you can register tools using standalone hooks tied to your component's mount and unmount lifecycle. The `useWebMCP` hook also provides schema-driven type inference and exposes local execution state.

## Angular support

Angular has [experimental support for WebMCP](https://angular.dev/ai/webmcp). If your application is already written with Angular, you can register tools tied to the application's dependency injection lifecycle and turn your Signal Forms into WebMCP tools.
