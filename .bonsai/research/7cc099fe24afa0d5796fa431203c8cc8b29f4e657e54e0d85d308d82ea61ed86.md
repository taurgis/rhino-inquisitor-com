## Compressed

### [14.3.] [New Registry for Service Parameters]

IANA has created the "Service Parameter Keys (SvcParamKeys)" registry in the "Domain Name System (DNS) Parameters" category on a new page entitled "DNS Service Bindings (SVCB)".

#### [14.3.1.] [Procedure]

A registration MUST include the following fields:[¶]

Number:

Wire-format numeric identifier (range 0-65535)[¶]

Name:

Unique presentation name[¶]

Meaning:

A short description[¶]

Reference:

Location of specification or registration source[¶]

Change Controller:

Person or entity, with contact information if appropriate[¶]

The characters in the registered Name field entry MUST be lowercase alphanumeric or "-" ([Section 2.1]). The name MUST NOT start with "key" or "invalid".[¶]

The registration policy for new entries is Expert Review (\[[RFC8126]\], [Section 4.5]). An entry MAY specify a reference of the form "Same as (other key name)" if it uses the same presentation and wire formats as an existing key.[¶]

This arrangement supports the development of new parameters while ensuring that zone files can be made interoperable.[¶]

## Detailed

### [14.3.](https://www.rfc-editor.org/info/rfc9460/#section-14.3) [New Registry for Service Parameters](https://www.rfc-editor.org/info/rfc9460/#name-new-registry-for-service-pa)

IANA has created the "Service Parameter Keys (SvcParamKeys)" registry in the "Domain Name System (DNS) Parameters" category on a new page entitled "DNS Service Bindings (SVCB)". This registry defines the namespace for parameters, including string representations and numeric SvcParamKey values. This registry is shared with other SVCB-compatible RR types, such as the HTTPS RR.[¶](https://www.rfc-editor.org/info/rfc9460/#section-14.3-1)

#### [14.3.1.](https://www.rfc-editor.org/info/rfc9460/#section-14.3.1) [Procedure](https://www.rfc-editor.org/info/rfc9460/#name-procedure)

A registration MUST include the following fields:[¶](https://www.rfc-editor.org/info/rfc9460/#section-14.3.1-1)

Number:

Wire-format numeric identifier (range 0-65535)[¶](https://www.rfc-editor.org/info/rfc9460/#section-14.3.1-2.2)

Name:

Unique presentation name[¶](https://www.rfc-editor.org/info/rfc9460/#section-14.3.1-2.4)

Meaning:

A short description[¶](https://www.rfc-editor.org/info/rfc9460/#section-14.3.1-2.6)

Reference:

Location of specification or registration source[¶](https://www.rfc-editor.org/info/rfc9460/#section-14.3.1-2.8)

Change Controller:

Person or entity, with contact information if appropriate[¶](https://www.rfc-editor.org/info/rfc9460/#section-14.3.1-2.10)

The characters in the registered Name field entry MUST be lowercase alphanumeric or "-" ([Section 2.1](https://www.rfc-editor.org/info/rfc9460/#presentation)). The name MUST NOT start with "key" or "invalid".[¶](https://www.rfc-editor.org/info/rfc9460/#section-14.3.1-3)

The registration policy for new entries is Expert Review (\[[RFC8126](https://www.rfc-editor.org/info/rfc9460/#RFC8126)\], [Section 4.5](https://rfc-editor.org/rfc/rfc8126#section-4.5)). The designated expert MUST ensure that the reference is stable and publicly available and that it specifies how to convert the SvcParamValue's presentation format to wire format. The reference MAY be any individual's Internet-Draft or a document from any other source with similar assurances of stability and availability. An entry MAY specify a reference of the form "Same as (other key name)" if it uses the same presentation and wire formats as an existing key.[¶](https://www.rfc-editor.org/info/rfc9460/#section-14.3.1-4)

This arrangement supports the development of new parameters while ensuring that zone files can be made interoperable.[¶](https://www.rfc-editor.org/info/rfc9460/#section-14.3.1-5)
