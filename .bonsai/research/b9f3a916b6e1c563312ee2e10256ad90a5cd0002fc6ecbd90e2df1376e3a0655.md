# URL Rules for SEO

To increase site traffic, optimize your site URLs for external search engines, such as Google or Yahoo. If you’re creating a site, URL Rules are automatically enabled and you can configure them if you have permissions to the URL Rules module. Salesforce recommends configuring and testing URL Rules on a Sandbox before exporting them to Staging and replicating them to Production.

Note Use the deprecated SEO support by [disabling the URL rules,] though Salesforce recommends that you use the URL Rules module. The URL Rules module and the (deprecated) SEO Support module can't be enabled at the same time.

The maximum length of a storefront URL is 1800 characters.

The maximum length of a URI plus query parameters request is 2002 characters.

Several settings apply across all URL types.

Optimize your site URLs in the following ways:

*   URLs shouldn't contain a page type indicator or a proprietary extension “sc.html”
*   Keep URLs short and meaningful
*   URLs shouldn't contain _demandware_

## Configuration in Business Manager

When you have enabled SEO URLs, you can [configure] them. Click App Launcher , and then select **Merchant Tools** | **Site** | **SEO & Discoverability** | **URL Rules** for:

*   [Category and Product URLs]
*   [Folder and Content Asset URLs]
*   [Pipeline URLs]
*   [Search Refinement URLs]

Also [resolve conflicts] and configure general [settings], and Review the [archive] on your Staging and Production instance.

## Permissions

The URL Rules module has a modular permission.

## Import and Export

URL rules import and export as part of the Site import/export module Site URLs item. To export the rules from the SEO Support module, these are still exported from the Site import/export module site preferences item.

Export the URL file as part of the existing Site URLs unit.

## Replication

Replicate the URL rules using the following replication tasks:

| Configuration | Replication Task |
| --- | --- |
| Category URLs | Site > Category URLs |
| Folder URLs | Site > Folder URLs |
| Pipeline URLs | Site > Pipeline URLs |
| URL rules | Site > Site URL Rules (or part of existing URL replication group) |

## Detailed

# URL Rules for SEO

To increase site traffic, optimize your site URLs for external search engines, such as Google or Yahoo. If you’re creating a site, URL Rules are automatically enabled and you can configure them if you have permissions to the URL Rules module. Salesforce recommends configuring and testing URL Rules on a Sandbox before exporting them to Staging and replicating them to Production. This topic applies to B2C Commerce.

![Note](https://sf-zdocs-cdn-prod.zoominsoftware.com/tdta-cc-b2c_merchandiser_administrator-262-0-0-production-enus/66b5e490-e0a9-4e6f-9968-ea252cfa6cfd/images/icon_note.png)

Note Use the deprecated SEO support by [disabling the URL rules,](https://help.salesforce.com/s/articleView?id=cc.b2c_enabling_search_friendly_urls.htm&language=en_US&type=5 "For your sitemap to include search-friendly URLs, turn them on them before creating your sitemap. Enable search-friendly URLs for your Production instance but not your Staging instance, because it makes it difficult to add content asset links based on URLs you want to link to.") though Salesforce recommends that you use the URL Rules module. The URL Rules module and the (deprecated) SEO Support module can't be enabled at the same time.

The maximum length of a storefront URL is 1800 characters. URLs that exceed this length are shortened, but are still valid and unique. In particular, product and content URLs still contain the product or content ID.

The maximum length of a URI plus query parameters request is 2002 characters. If the request exceeds this limit, the page returns a 404 error.

Several settings apply across all URL types. These include localization, capitalization, and space encoding in URLs.

Optimize your site URLs in the following ways:

*   URLs shouldn't contain a page type indicator or a proprietary extension “sc.html”
*   Keep URLs short and meaningful
*   URLs shouldn't contain _demandware_
