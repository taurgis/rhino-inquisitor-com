## Compressed

### The Await and Suspense Pattern

React Router’s `Await` component addresses both limitations. It resolves the Promise inline via a render prop, eliminating the need for a separate component, and accepts an optional `errorElement` prop that catches rejections locally, keeping the loading and error boundary co-located with the async operation.

```jsx
<Suspense fallback={<Skeleton />}>
  <Await resolve={nonCritical}>{(resolved) => <NonCriticalContent data={resolved} />}</Await>
</Suspense>
```

When a Promise passed to `Await` rejects, the error propagates to the nearest error boundary in the tree. For more granular control, `Await` accepts an optional `errorElement` prop that catches rejections locally without affecting the rest of the route.

```jsx
<Suspense fallback={<Skeleton />}>
  <Await resolve={nonCritical} errorElement={<ErrorFallback />}>
    {(resolved) => <NonCriticalContent data={resolved} />}
  </Await>
</Suspense>
```
