## Summary

B2C Commerce API Release Notes > 09/22/2026 > SLAS Release

## Compressed

### SLAS Release

- Infrastructure updates.
- Fixed an intermittent bad signature verifier error on /userinfo that could occur during tenant signing key rotation. Tokens signed with the previous key are now accepted during the rotation window, and token handling has been strengthened to ensure signatures are fully verified.
- **Fixed Trusted-Agent guest flow authorization errors**: Resolved a 403 SSO Unauthorized error that could occur in the Trusted-Agent guest flow (/trusted-agent/callback → /token) when client-state pass-through was enabled. Guest sessions now complete successfully in this scenario.
- **Improved IDP error message clarity**: Updated IDP error messages returned as 412 responses to clearly distinguish between missing configuration fields and IDP HTTP errors. There is no behavioral change, and detailed error message exposure remains controlled by the existing configuration setting.
- **mTLS Enforcement**
  - To enhance the security of the SLAS authentication service, we’re enabling mutual TLS (mTLS) client-certificate enforcement at the SLAS gateway. Starting October 6, 2026, according to the new per-region schedule listed below, any request reaching the SLAS origin without a valid client certificate—including requests that bypass the SCAPI zone—will be rejected.
  - Who is affected:
    - No action required: for integrations using the standard, published Commerce Cloud SLAS endpoints through the SCAPI zone. This is the supported integration path and will continue to work without changes.
    - Action required: for integrations that connect directly to the SLAS origin and bypass the SCAPI zone—for example, by using hardcoded origin hostnames/IP addresses or a custom network path. These requests will be rejected once mTLS enforcement is enabled.
  - Schedule:
    - AP2: October 6, 2026
    - AP3: October 8, 2026
    - EU: October 12, 2026
    - US East: October 15, 2026
