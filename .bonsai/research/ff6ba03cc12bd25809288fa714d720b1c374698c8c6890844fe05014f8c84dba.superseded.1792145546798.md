## Summary

B2C Commerce API Release Notes > 09/25/2026 > SCAPI Release

## Compressed

### SCAPI Release

New APIs:

- [Deployments] 1.0.5
  - Upload versioned server-side rendering (SSR) bundles and deploy them to a storefront environment on Managed Runtime.
  - Endpoints:
    - `GET/POST /organizations/{organizationId}/storefronts/{storefrontId}/bundles`
    - `GET/POST /organizations/{organizationId}/storefronts/{storefrontId}/environments/{environmentId}/deployments`
    - `GET /organizations/{organizationId}/storefronts/{storefrontId}/environments/{environmentId}/deployments/{deploymentId}`
- [Environments] 1.0.3
  - SCAPI-native access to Managed Runtime environments for a storefront: create, list, update display name, delete, clone, and promote to primary.
  - Also manages environment variables, CDN cache invalidations, header-based access control, and URL redirects.
  - Environment create/delete are asynchronous. Poll the environment by ID.
  - Endpoints:
    - `GET/POST /organizations/{organizationId}/storefronts/{storefrontId}/environments`
    - `POST /organizations/{organizationId}/storefronts/{storefrontId}/environments/clone`
    - `GET/PATCH/DELETE /organizations/{organizationId}/storefronts/{storefrontId}/environments/{environmentId}`
    - `PUT /organizations/{organizationId}/storefronts/{storefrontId}/environments/{environmentId}/primary`
    - `POST /organizations/{organizationId}/storefronts/{storefrontId}/environments/{environmentId}/cache-invalidations`
    - `GET/PATCH /organizations/{organizationId}/storefronts/{storefrontId}/environments/{environmentId}/environment-variables`
    - `GET/POST /organizations/{organizationId}/storefronts/{storefrontId}/environments/{environmentId}/access-control-headers`
    - `GET/DELETE /organizations/{organizationId}/storefronts/{storefrontId}/environments/{environmentId}/access-control-headers/{accessControlHeaderId}`
    - `GET/POST /organizations/{organizationId}/storefronts/{storefrontId}/environments/{environmentId}/redirects`
    - `GET/PATCH/DELETE /organizations/{organizationId}/storefronts/{storefrontId}/environments/{environmentId}/redirects/{redirectId}`
    - `POST /organizations/{organizationId}/storefronts/{storefrontId}/environments/{environmentId}/redirects/actions/clone`
- [Storefronts] 1.0.2
  - Added SCAPI-native provisioning for Storefront Next and partial administration for PWA Kit. This API replaces the Business Manager and Data API setup flow so that the CLI and tooling can automate the storefront lifecycle.
  - Create and delete operations are asynchronous. The API returns immediately. Poll the storefront by ID until setup completes.
  - Endpoints:
    - `GET /organizations/{organizationId}/storefronts`
    - `POST /organizations/{organizationId}/storefronts`: The first request returns 202. A retry with the same name returns 409 while the record exists.
    - `GET /organizations/{organizationId}/storefronts/{storefrontId}`
    - `PATCH /organizations/{organizationId}/storefronts/{storefrontId}`: Replaces the assigned sites list.
    - `DELETE /organizations/{organizationId}/storefronts/{storefrontId}`: The first request returns 202. After the storefront is deleted, a retry returns 404.

Updated APIs:

- [Auth Admin] 1.19.0
  - Log out up to 50 shoppers in one request by `loginId`. This request revokes refresh tokens and inactivates access tokens across all sessions. Shoppers must sign in again. Passwords are unchanged.
  - The API skips duplicate `loginId` values as `not_processed`. The response reports `success`, `failure`, or `not_processed` for each `loginId`.
  - New endpoint:
    - `POST /tenants/{tenantId}/batch-logout`
  - For details, see [Log Out Multiple Shoppers].
- [Experiences] 1.4.0
  - Added admin retrieval of Page Designer types for a site. The `siteId` query parameter is required.
  - New endpoints:
    - `GET /organizations/{organizationId}/component-types`: Returns component types with group, region definitions, and attribute definitions.
    - `GET /organizations/{organizationId}/page-types`: Returns page types with region definitions, attribute definitions, and supported aspect types.
- [Orders] 1.6.4
  - Added normalized, read-only payment enrichment on existing order resources. The API omits these objects when no data is available. Historical orders remain readable.
  - `PaymentInstrument.fraudDecisions`: `preAuthorization` and `postAuthorization`.
  - `PaymentInstrument.paymentDetails`: `type`, `brand`, `last4`, `walletType`, `expirationMonth`, `expirationYear`, `token`, `tokenType`, `accountHolderName`, `bin`, `dpanLast4`, `issuingCountry`, and `fundingType`.
  - `PaymentTransaction.transactionDetails`: `cvcResult`, `avsResult`, `threeDSResult`, `threeDSVersion`, `threeDSTransactionId`, `electronicCommerceIndicator`, `approvalCode`, `reasonCode`, and `processorResponseText`.
- [Price Books] 1.1.0
  - Added create, read, update, and delete (CRUD) for price books, price book entries, and site assignments. Search remains available. List endpoints return paginated results without a search query.
  - Price books created through this API are always type `standard`. For `feed_based` price books, metadata remains editable. Writes to price book entries are rejected.
  - Supports quantity-tier pricing through `priceTables` (absolute amount or percentage discount, each with a validity window). A PATCH replaces the `priceTables` array.
  - New endpoints:
    - `GET /organizations/{organizationId}/price-books`
    - `GET/PUT/PATCH/DELETE /organizations/{organizationId}/price-books/{priceBookId}`
    - `GET /organizations/{organizationId}/price-books/{priceBookId}/price-book-entries`
    - `GET/PUT/PATCH/DELETE /organizations/{organizationId}/price-books/{priceBookId}/price-book-entries/{productId}`
    - `GET /organizations/{organizationId}/price-books/{priceBookId}/site-assignments`
    - `PUT/DELETE /organizations/{organizationId}/price-books/{priceBookId}/site-assignments/{siteId}` — `PUT` is idempotent: HTTP 201 when newly assigned, HTTP 200 when already assigned.
- [Promotions] 1.2.0
  - `GET/PUT/PATCH /promotions/{id}/compatibility`
  - `GET/PUT/PATCH/DELETE /promotions/{id}/discount-rule`
- [Replications] 1.0.8
  - Documentation update for timeouts and RFC 7807 error handling.
- [Shopper Baskets V2] 2.13.4
  - `OrderPaymentInstrument` now includes shopper-safe, read-only `fraudDecisions` (`preAuthorization` only) and `paymentDetails` (`type`, `brand`, `last4`, `walletType`, `expirationMonth`, `expirationYear`, `token`, `tokenType`, and `accountHolderName`).
- [Shopper Customers] 1.10.0
  - Completes saved-payment setup after the provider succeeds (registered customer ShopperToken only). `paymentMethodReferenceSetupId` is the provider setup identifier (for example a Stripe SetupIntent ID).
  - `gatewayProperties` is no longer required on payment-method-reference setup.
  - `CustomerPaymentMethodReference` now returns read-only `accountHolderName` (SEPA), and `brand` / `expiryMonth` / `expiryYear` (cards).
  - Embedded Product includes `slug` and `primaryCategory`.
  - New endpoint:
    - `POST /customers/{customerId}/payment-method-references/actions/complete`
- [Shopper Orders] 1.22.4
  - Added the same `fraudDecisions` and `paymentDetails` enrichment as Shopper Baskets V2.
  - `OmsReturnProductItem.reasonText`: optional free-text note alongside the coded return reason.
- [Shopper Payments] 1.7.0
  - `POST /payment-instruments/balance` is provider-generic instead of gift-card-specific.
  - The request now requires `provider` and `providerProperties` instead of `giftCard`. Don't send PCI data (PAN). Use a client-side token or encrypted fields.
- [Shopper Products] 1.13.0
  - When the Enable Shopper SEO Slug (CFT) feature toggle is on, Shopper Products returns an SEO slug for the request locale, generated from the site’s storefront URL rules. `getCategory` and `getCategories` accept a category ID or `slug`, and the `category` and each `parentCategoryTree` entry include `slug`. A product includes `slug` only when `expand=slug` is requested, and its primary category includes `slug` when `expand=primary_category` is requested. The toggle is off by default, so existing requests continue to return categories by ID and omit `slug`. To enable the feature toggle, contact Customer Support.
- [Shopper Search] 1.15.0
  - Added `SuggestedProduct.slug` for SEO-friendly suggestion links. This is the slug segment, not a full URL.
