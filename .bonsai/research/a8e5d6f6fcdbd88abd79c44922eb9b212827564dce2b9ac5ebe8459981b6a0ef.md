# Session data best practices for a B2C Commerce storefront

Publish Date: Jul 30, 2026

Description

When a B2C Commerce storefront is deployed, you may see a deprecation warning in Business Manager under **Administration > Site Development > Deprecated API Usage**. The warning message reads:

_Type 'X' not allowed as attribute value for a session._
  

### Probable Cause

This warning is generated because B2C Commerce enforces strict rules on what types of data can be stored in a storefront session.
  

### Real-Life Example

A B2C Commerce developer stores the current customer's full `dw.catalog.ProductSearchModel` object in the session to avoid re-running the search on each page request. This works in development but causes a deprecation warning in Business Manager on staging. When a peak-season flash sale drives 50× normal traffic, the serialised session data exhausts server memory and the storefront produces OutOfMemory errors — bringing the site down. **Resolution:** Replace the persisted `ProductSearchModel` object with a primitive string (e.g. the serialised query string or a product ID) and re-run the search from the string on each request. This keeps session data within the 4 KB serialised size limit and eliminates the deprecation warning.
  
  

Resolution

Follow the recommendations shared in the documentation of the [**Class Session**].

### Session Data Storage Rules for B2C Commerce

_The B2C Commerce Class Session API enforces the following rules for what and how much data can be stored in a B2C Commerce storefront session. Follow these rules to resolve the deprecation warning and ensure your storefront remains stable at scale. **Supported data types (safe to store in session):** _

*   All primitive types: `boolean`, `number`, `string`, `Number`, `String`, `Boolean`, `Date`
*   All B2C Commerce value types: `Money`, `Quantity`, `Decimal`, `Calendar`

_**Unsupported data types (must not be stored in session):** _

*   Persistent objects (e.g. `dw.catalog.Product`, `dw.order.Basket`)
*   Collections (e.g. arrays, lists)
*   Scripted objects (custom script classes)

_**Size limits:** _

*   Individual strings are limited to **2,000 characters**
*   The total serialised session is limited to **4 KB**

_**Important:** From compatibility mode **19.10** onwards, attempting to store an unsupported type throws an exception — it is no longer silently accepted.

# Session data best practices for a B2C Commerce storefront

Publish Date: Jul 30, 2026

Description

When a B2C Commerce storefront is deployed, you may see a deprecation warning in Business Manager under **Administration > Site Development > Deprecated API Usage**. The warning message reads:

_Type 'X' not allowed as attribute value for a session._  
  

### Probable Cause

This warning is generated because B2C Commerce enforces strict rules on what types of data can be stored in a storefront session. These restrictions exist to control the maximum size of serialised session data and prevent scalability issues at high traffic volumes.  
When session data is unrestricted in type or size, the session storage grows unpredictably. As concurrent sessions increase during peak traffic, uncontrolled session size can exhaust server memory and produce **OutOfMemory errors**, causing the production storefront to go down.  
The more sessions that are created, the more memory session data consumes. Without enforced type and size limits on session data, there is no mechanism to cap the maximum size of a serialised session — making high-traffic events a reliability risk.  
  

### Real-Life Example

A B2C Commerce developer stores the current customer's full `dw.catalog.ProductSearchModel` object in the session to avoid re-running the search on each page request. This works in development but causes a deprecation warning in Business Manager on staging. When a peak-season flash sale drives 50× normal traffic, the serialised session data exhausts server memory and the storefront produces OutOfMemory errors — bringing the site down.  
**Resolution:** Replace the persisted `ProductSearchModel` object with a primitive string (e.g. the serialised query string or a product ID) and re-run the search from the string on each request. This keeps session data within the 4 KB serialised size limit and eliminates the deprecation warning.  
  
  

Resolution

Follow the recommendations shared in the documentation of the [**Class Session**](https://salesforcecommercecloud.github.io/b2c-dev-doc/docs/current/scriptapi/html/index.html?target=class_dw_system_Session.html).  

### Session Data Storage Rules for B2C Commerce

_The B2C Commerce Class Session API enforces the following rules for what and how much data can be stored in a B2C Commerce storefront session. Follow these rules to resolve the deprecation warning and ensure your storefront remains stable at scale.  
**Supported data types (safe to store in session):**  
_

*   All primitive types: `boolean`, `number`, `string`, `Number`, `String`, `Boolean`, `Date`
*   All B2C Commerce value types: `Money`, `Quantity`, `Decimal`, `Calendar`

_**Unsupported data types (must not be stored in session):**  
_

*   Persistent objects (e.g. `dw.catalog.Product`, `dw.order.Basket`)
*   Collections (e.g. arrays, lists)
*   Scripted objects (custom script classes)

_**Size limits:**  
_

*   Individual strings are limited to **2,000 characters**
*   The total serialised session is limited to **4 KB**

_**Important:** From compatibility mode **19.10** onwards, attempting to store an unsupported type throws an exception — it is no longer silently accepted. In earlier versions, the unsupported value was stored but with undefined behaviour.
