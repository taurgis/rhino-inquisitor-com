## Reproducibility Statement

We provide all materials to reproduce our results. Algorithms are specified in Sections [4.2](https://arxiv.org/html/2510.15061#S4.SS2 "4.2 Soft Banning: Configurable Suppression Strength ‣ 4 The Antislop Sampler ‣ Antislop: A Comprehensive Framework for Identifying and Eliminating Repetitive Patterns in Language Models")–[5.2](https://arxiv.org/html/2510.15061#S5.SS2 "5.2 The FTPO Formulation ‣ 5 Final Token Preference Optimization (FTPO) ‣ Antislop: A Comprehensive Framework for Identifying and Eliminating Repetitive Patterns in Language Models") including loss definitions and hyperparameters. The general configuration template for FTPO/DPO training configuration, LoRA settings, early-stopping criteria, and decoding parameters are given in App. [M](https://arxiv.org/html/2510.15061#A13 "Appendix M Auto-antislop Configuration File for gemma-3-12b-it 2k Banlist Size ‣ Antislop: A Comprehensive Framework for Identifying and Eliminating Repetitive Patterns in Language Models"). In addition, the data pipeline, prompts, judge rubric, and scoring template are included (Fig. [10](https://arxiv.org/html/2510.15061#A8.F10 "Figure 10 ‣ Appendix H Writing Quality Rubric Prompt ‣ Antislop: A Comprehensive Framework for Identifying and Eliminating Repetitive Patterns in Language Models")). For inference with Antislop, we describe the implementation and throughput (App. [B](https://arxiv.org/html/2510.15061#A2 "Appendix B Inference Performance (tok/s) ‣ Antislop: A Comprehensive Framework for Identifying and Eliminating Repetitive Patterns in Language Models")), and include our antislop-vllm implementation in supplementary materials. The supplemental materials contain necessary code and example configuration files to run Antislop Sampler and the automated training pipeline with FTPO or DPO.
