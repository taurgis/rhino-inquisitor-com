# The Shopper Login and API Access Service(SLAS) Session Bridge DWSID GUEST Deprecation

Publish Date: Feb 7, 2024

Description

Over the past several months, Salesforce internal teams have worked to provide a **HUGE performance improvement** to the SLAS, Session-bridge (SESB) GUEST API. The improvement, which replaces the SESB DW session ID (DWSID) based flow, is called the SESB signed **guest** session token flow (SESB DWSGST) and **will reduce latency by 1 SECOND on each call**. As of **March 31, 2024**, SLAS will no longer support the SESB DWSID parameter for GUESTs on /session-bridge/token calls.

Resolution

​​​​​​**What this deprecation means for the merchant:**

The merchant will no longer be able to use the DWSID parameter and loginId=guest on the /session-bridge/token after **March 31st, 2024**.

A response similar to the below one may be thrown:

\[plugin\_slas\] getSessionBridgeAccessToken sessionBridgeTokenResponse: {"body":null,"headers":{"map":{}},"ok":false,"status":410,"statusText":"Gone","url":"[https://{{shortcode}}.api.commercecloud.salesforce.com/shopper/auth/v1/organizations/{{organization\_id}}/oauth2/session-bridge/token?grant\_type=session\_bridge&code\_verifier={{code\_verifier}}&channel\_id={{site\_id}}&login\_id=guest&usid={{user\_id}}&dwsid={{dwsid}}&client\_id={{client\_id}}]","errorText":"{\\"title\\":\\"Gone\\",\\"type\\":\\"[https://api.commercecloud.salesforce.com/documentation/error/v1/errors/gone]\\",\\"detail\\":\\"Gone\\"}"}

**Why are we deprecating the DWSID/loginID=guest parameter:** Calls to SLAS /session-bridge/token with DWSID and loginID=guest - forces SLAS to make calls over to eCom each and every time to verify that the DWSID is valid. The DWSGST option has replaced this flow, and eliminates the calls to eCom, leaving more resources on eCom to process orders.

**Action Items:**

1.  Customers currently using PlugIn\_SLAS - **Transition to plugin\_slas v7.1** (by default this uses DWSGST)
2.  Customers NOT using Plugin\_SLAS - **Manually code in DWSGST**
    1.  On first arrival to eCom, get DWSID cookie per usual
    2.  then call eCom scriptAPI to get a “Signed Guest Session”
        1.  session.generateGuestSessionSignature() return DWSGST
        2.  Documentation [here]
    3.  call SLAS SESB with DWSGT token
        1.  SLAS will validate the clientID/secret and then validate the DWSGST
        2.  and return a SLAS guest shopper JWT that comes with the same eCom customer ID assigned during the DWSID creation
    4.  done, continue your existing processing

# The Shopper Login and API Access Service(SLAS) Session Bridge DWSID GUEST Deprecation

Publish Date: Feb 7, 2024

Description

Over the past several months, Salesforce internal teams have worked to provide a **HUGE performance improvement** to the SLAS, Session-bridge (SESB) GUEST API. The improvement, which replaces the SESB DW session ID (DWSID) based flow, is called the SESB signed **guest** session token flow (SESB DWSGST) and **will reduce latency by 1 SECOND on each call**. The feature went GA on SLAS and eCom in the Spring of 2023 - and shortly the plugin\_slas v7.1 will be released which also supports this much responsive flow. As of **March 31, 2024**, SLAS will no longer support the SESB DWSID parameter for GUESTs on /session-bridge/token calls. To get ahead of this, we are encouraging all of the tenants to transition to SESB DWSGST. We are adding an allow list with the current PRD tenants, all other tenants will no longer be able to use the DWSID param for GUESTs - the allow list will go into effect on or before Sept 31, 2023. If exceptions are needed, please contact Salesforce Support.

Resolution

​​​​​​**What this deprecation means for the merchant:**

The merchant will no longer be able to use the DWSID parameter and loginId=guest on the /session-bridge/token after **March 31st, 2024**. Beyond this timeline, accessing this API will return a _404 error_ and prevent your guest shoppers access to your storefront.

 A response similar to the below one may be thrown:

The DWSGST option has replaced this flow, and eliminates the calls to eCom, leaving more resources on eCom to process orders. See [Guide on SLAS](https://developer.salesforce.com/docs/commerce/commerce-api/guide/get-started.html) and resources for additional help can be found on our [documentation page.](https://developer.salesforce.com/docs/commerce/commerce-api/references/shopper-login?meta=Summary)
