## Compressed

## [11\.] [Interaction with Other Standards]

This standard is intended to reduce connection latency and improve user privacy.

To realize the greatest privacy benefits, this proposal is intended for use over a privacy\-preserving DNS transport (like DNS over TLS \[[DoT]\] or DNS over HTTPS \[[DoH]\]). However, performance improvements, and some modest privacy improvements, are possible without the use of those standards.[¶]

Any specification for the use of SVCB with a protocol MUST have an entry for its scheme under the SVCB RR type in the IANA DNS "Underscored and Globally Scoped DNS Node Names" registry \[[Attrleaf]\]. The scheme MUST have an entry in the "Uniform Resource Identifier (URI) Schemes" registry \[[RFC7595]\] and MUST have a defined specification for use with SVCB.[¶]

## [11\.](https://www.rfc-editor.org/info/rfc9460/#section-11) [Interaction with Other Standards](https://www.rfc-editor.org/info/rfc9460/#name-interaction-with-other-stan)

This standard is intended to reduce connection latency and improve user privacy. Server operators implementing this standard SHOULD also implement TLS 1.3 \[[RFC8446](https://www.rfc-editor.org/info/rfc9460/#RFC8446)\] and Online Certificate Status Protocol (OCSP) Stapling (i.e., Certificate Status Request in [Section 8](https://rfc-editor.org/rfc/rfc6066#section-8) of \[[RFC6066](https://www.rfc-editor.org/info/rfc9460/#RFC6066)\]), both of which confer substantial performance and privacy benefits when used in combination with SVCB records.[¶](https://www.rfc-editor.org/info/rfc9460/#section-11-1)

To realize the greatest privacy benefits, this proposal is intended for use over a privacy\-preserving DNS transport (like DNS over TLS \[[DoT](https://www.rfc-editor.org/info/rfc9460/#RFC7858)\] or DNS over HTTPS \[[DoH](https://www.rfc-editor.org/info/rfc9460/#RFC8484)\]). However, performance improvements, and some modest privacy improvements, are possible without the use of those standards.[¶](https://www.rfc-editor.org/info/rfc9460/#section-11-2)

Any specification for the use of SVCB with a protocol MUST have an entry for its scheme under the SVCB RR type in the IANA DNS "Underscored and Globally Scoped DNS Node Names" registry \[[Attrleaf](https://www.rfc-editor.org/info/rfc9460/#RFC8552)\]. The scheme MUST have an entry in the "Uniform Resource Identifier (URI) Schemes" registry \[[RFC7595](https://www.rfc-editor.org/info/rfc9460/#RFC7595)\] and MUST have a defined specification for use with SVCB.[¶](https://www.rfc-editor.org/info/rfc9460/#section-11-3)
