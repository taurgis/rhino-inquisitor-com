## Compressed

### [10.2.] [Structuring Zones for Performance]

To avoid a delay for clients using a non-conforming recursive resolver, domain owners SHOULD minimize the use of AliasMode records and SHOULD choose TargetName according to a predictable convention that is known to the client, so that clients can issue A and/or AAAA queries for TargetName in advance (see [Section 5]).

## Detailed

### [10.2.](https://www.rfc-editor.org/info/rfc9460/#section-10.2) [Structuring Zones for Performance](https://www.rfc-editor.org/info/rfc9460/#name-structuring-zones-for-perfo)

To avoid a delay for clients using a non-conforming recursive resolver, domain owners SHOULD minimize the use of AliasMode records and SHOULD choose TargetName according to a predictable convention that is known to the client, so that clients can issue A and/or AAAA queries for TargetName in advance (see [Section 5](https://www.rfc-editor.org/info/rfc9460/#optimizations)). Unless otherwise specified, the convention is to set TargetName to the service name for an initial ServiceMode record, or to "." if it is reached via an alias.[¶](https://www.rfc-editor.org/info/rfc9460/#section-10.2-1)

[Figure 1](https://www.rfc-editor.org/info/rfc9460/#figure-1): ["foo://foo.example.com:8080" Is Available at "foosvc.example.net", but "bar://bar.example.com:9090" Is Served Locally](https://www.rfc-editor.org/info/rfc9460/#name-foo-fooexamplecom8080-is-av)

Domain owners SHOULD avoid using a TargetName that is below a DNAME, as this is likely unnecessary and makes responses slower and larger. Also, zone structures that require following more than eight aliases (counting both AliasMode and CNAME records) are NOT RECOMMENDED.[¶](https://www.rfc-editor.org/info/rfc9460/#section-10.2-3)
