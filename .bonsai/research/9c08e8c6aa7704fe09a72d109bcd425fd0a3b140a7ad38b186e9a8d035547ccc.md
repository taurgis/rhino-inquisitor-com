An [Nmtoken] (name token) is any mixture of name characters.

\[Definition: A [Name] is an [Nmtoken] with a restricted set of initial characters.\] Disallowed initial characters for [Names] include digits, diacritics, the full stop and the hyphen.

Names beginning with the string "`xml`", or with any string which would match `(('X'|'x') ('M'|'m') ('L'|'l'))`, are reserved for standardization in this or future versions of this specification.

**Note:**

The Namespaces in XML Recommendation [\[XML Names\]] assigns a meaning to names containing colon characters. Therefore, authors should not use the colon in XML names except for namespace purposes, but XML processors must accept the colon as a name character.

The first character of a [Name] _MUST_ be a [NameStartChar], and any other characters _MUST_ be [NameChars]; this mechanism is used to prevent names from beginning with European (ASCII) digits or with basic combining characters. Document authors are encouraged to use names which are meaningful words or combinations of words in natural languages, and to avoid symbolic or white space characters in names.

The ASCII symbols and punctuation marks, along with a fairly large group of Unicode symbol characters, are excluded from names because they are more useful as delimiters in contexts where XML names are used outside XML documents; providing this group gives those contexts hard guarantees about what _cannot_ be part of an XML name.

## Detailed

### 2.3 Common Syntactic Constructs

This section defines some symbols used widely in the grammar.

[S](https://www.w3.org/TR/xml/#NT-S) (white space) consists of one or more space (#x20) characters, carriage returns, line feeds, or tabs.

##### White Space

| [3] | S | ::= | (#x20 \| #x9 \| #xD \| #xA)+ |
| --- | --- | --- | --- |

**Note:**

The presence of #xD in the above production is maintained purely for backward compatibility with the [First Edition](https://www.w3.org/TR/1998/REC-xml-19980210). As explained in [**2.11 End-of-Line Handling**](https://www.w3.org/TR/xml/#sec-line-ends), all #xD characters literally present in an XML document are either removed or replaced by #xA characters before any other processing is done. The only way to get a #xD character to match this production is to use a character reference in an entity value literal.

An [Nmtoken](https://www.w3.org/TR/xml/#NT-Nmtoken) (name token) is any mixture of name characters.

\[Definition: A [Name](https://www.w3.org/TR/xml/#NT-Name) is an [Nmtoken](https://www.w3.org/TR/xml/#NT-Nmtoken) with a restricted set of initial characters.\] Disallowed initial characters for [Names](https://www.w3.org/TR/xml/#NT-Name) include digits, diacritics, the full stop and the hyphen.

Names beginning with the string "`xml`", or with any string which would match `(('X'|'x') ('M'|'m') ('L'|'l'))`, are reserved for standardization in this or future versions of this specification.

**Note:**

The Namespaces in XML Recommendation [\[XML Names\]](https://www.w3.org/TR/xml/#xml-names) assigns a meaning to names containing colon characters. Therefore, authors should not use the colon in XML names except for namespace purposes, but XML processors must accept the colon as a name character.

The first character of a [Name](https://www.w3.org/TR/xml/#NT-Name) _MUST_ be a [NameStartChar](https://www.w3.org/TR/xml/#NT-NameStartChar), and any other characters _MUST_ be [NameChars](https://www.w3.org/TR/xml/#NT-NameChar); this mechanism is used to prevent names from beginning with European (ASCII) digits or with basic combining characters. Almost all characters are permitted in names, except those which either are or reasonably could be used as delimiters. The intention is to be inclusive rather than exclusive, so that writing systems not yet encoded in Unicode can be used in XML names. See [**J Suggestions for XML Names**](https://www.w3.org/TR/xml/#sec-suggested-names) for suggestions on the creation of names.

Document authors are encouraged to use names which are meaningful words or combinations of words in natural languages, and to avoid symbolic or white space characters in names. Note that COLON, HYPHEN-MINUS, FULL STOP (period), LOW LINE (underscore), and MIDDLE DOT are explicitly permitted.

The ASCII symbols and punctuation marks, along with a fairly large group of Unicode symbol characters, are excluded from names because they are more useful as delimiters in contexts where XML names are used outside XML documents; providing this group gives those contexts hard guarantees about what _cannot_ be part of an XML name. The character #x037E, GREEK QUESTION MARK, is excluded because when normalized it becomes a semicolon, which could change the meaning of entity references.

##### Names and Tokens

| [4] | NameStartChar | ::= | ":" \| [A-Z] \| "_" \| [a-z] \| [#xC0-#xD6] \| [#xD8-#xF6] \| [#xF8-#x2FF] \| [#x370-#x37D] \| [#x37F-#x1FFF] \| [#x200C-#x200D] \| [#x2070-#x218F] \| [#x2C00-#x2FEF] \| [#x3001-#xD7FF] \| [#xF900-#xFDCF] \| [#xFDF0-#xFFFD] \| [#x10000-#xEFFFF] |
| --- | --- | --- | --- |
| [4a] | NameChar | ::= | NameStartChar \| "-" \| "." \| [0-9] \| #xB7 \| [#x0300-#x036F] \| [#x203F-#x2040] |
| [5] | Name | ::= | NameStartChar (NameChar)* |
| [6] | Names | ::= | Name (#x20 Name)* |
| [7] | Nmtoken | ::= | (NameChar)+ |
| [8] | Nmtokens | ::= | Nmtoken (#x20 Nmtoken)* |

Literal data is any quoted string not containing the quotation mark used as a delimiter for that string. Literals are used for specifying the content of internal entities ([EntityValue](https://www.w3.org/TR/xml/#NT-EntityValue)), the values of attributes ([AttValue](https://www.w3.org/TR/xml/#NT-AttValue)), and external identifiers ([SystemLiteral](https://www.w3.org/TR/xml/#NT-SystemLiteral)). Note that a [SystemLiteral](https://www.w3.org/TR/xml/#NT-SystemLiteral) can be parsed without scanning for markup.

##### Literals

| [9] | EntityValue | ::= | '"' ([^%&"] \| PEReference \| Reference)* '"' |
| --- | --- | --- | --- |
|  |  |  | \| "'" ([^%&'] \| PEReference \| Reference)* "'" |
| [10] | AttValue | ::= | '"' ([^<&"] \| Reference)* '"' |
|  |  |  | \| "'" ([^<&'] \| Reference)* "'" |
| [11] | SystemLiteral | ::= | ('"' [^"]* '"') \| ("'" [^']* "'") |
| [12] | PubidLiteral | ::= | '"' PubidChar* '"' \| "'" (PubidChar - "'")* "'" |
| [13] | PubidChar | ::= | #x20 \| #xD \| #xA \| [a-zA-Z0-9] \| [-'()+,./:=?;!*#@$_%] |

**Note:**

Although the [EntityValue](https://www.w3.org/TR/xml/#NT-EntityValue) production allows the definition of a general entity consisting of a single explicit `<` in the literal (e.g., `<!ENTITY mylt "<">`), it is strongly advised to avoid this practice since any reference to that entity will cause a well-formedness error.
