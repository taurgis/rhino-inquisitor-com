# RHI-094 Hugo Crash and HOLD Drift Remediation (2026-03-23)

## Change summary

Four ordered remediation phases were applied:

1. Phase 1: fixed the Hugo production-build crash that blocked local verification.
2. Phase 2: cleaned HOLD-only caption-drift routes for affected batches by removing drift-prone figcaption text and invalid shortcode-link wrappers.
3. Phase 3: normalized shortcode caption rendering so HTML entities in caption parameters no longer surface literally in visible figcaptions.
4. Phase 4: removed synthetic video figcaptions unless an article explicitly opts in to a visible watch-link caption.

## Why this changed

- Local verification was blocked by a Hugo panic (`Error allocating memory for blob data` followed by `panic: call with ID 0 not found`) during `hugo --minify --environment production`.
- The latest article audit contained HOLD-only caption drift findings in the affected batch set (batch 14 and batch 15), creating unresolved closeout work after the crash fix.
- Caption strings copied from source content still included HTML entities such as `&quot;`, which the shortcode rendered literally in visible figcaptions.
- The batch 9 rerun still surfaced a local-only `Watch on YouTube` figcaption generated by the shared `video-embed` shortcode even when the live article had no visible caption.

## Behavior details

### Phase 1: Hugo crash stabilization

Old behavior:
- `img-caption` rendered through `media/image.html`, which always processed processable images (`.Process` and optional responsive derivatives).
- With large caption-migration scope active, this path could trigger Hugo warpc memory instability and panic during production build.

New behavior:
- `media/image.html` now supports an optional `process` toggle (default remains `true` for existing callers).
- `img-caption` now calls `media/image.html` with `process=false`, preserving local-resource resolution and dimensions while bypassing expensive transform work in this shortcode path.
- Production build is restored as a stable verification gate.

### Phase 2: HOLD-only caption drift cleanup

Old behavior:
- Affected HOLD-only routes in batch 14 and batch 15 contained caption text that drifted from live parity expectations.
- Several routes also used invalid markdown-link wrappers around the shortcode form (`[{{< img-caption ... >}}](...)`).

New behavior:
- Removed markdown-link wrappers around `img-caption` in the affected HOLD-only route set.
- Removed `caption="..."` attributes for the same HOLD-only routes to eliminate drift-prone figcaption output while preserving image rendering and alt text.
- Scope intentionally excluded HIGH FAIL routes in the same batches.

### Phase 3: caption entity normalization

Old behavior:
- `img-caption` rendered the `caption` parameter as-is.
- HTML entities inside caption text, such as `&quot;`, appeared literally in the visible figcaption.

New behavior:
- `img-caption` now HTML-unescapes caption text before rendering the figcaption.
- Existing article content can keep encoded quote entities in shortcode parameters without exposing `&quot;` in the rendered page.
- Residual batch fixes can focus on caption parity rather than entity-formatting artifacts.

### Phase 4: synthetic video-caption removal

Old behavior:
- `video-embed` always rendered a visible figcaption with a `Watch on YouTube` link.
- Articles that embedded a video but did not have a corresponding live figcaption accumulated local-only caption drift in the audit.

New behavior:
- `video-embed` now renders the watch-link figcaption only when a caller explicitly passes `showWatchLink=true`.
- Existing video embeds no longer generate synthetic visible captions by default.
- Batch parity review can distinguish intentional video captions from shortcode-generated noise.

## Impact

- Maintainers can run local Hugo production validation again without crash.
- HOLD-only caption drift backlog for affected batch 14/15 routes is reduced by removing caption-text variance from those routes.
- Core shortcode semantics and image rendering remain intact; only processing behavior and caption decoding in the `img-caption` path changed.
- Shared video embeds now default to captionless output unless a visible watch-link caption is explicitly requested.

## Verification

1. Crash reproduction (before fix):
- `hugo --minify --environment production`
- Observed: repeated blob-memory allocation errors and warpc panic.

2. Crash fix validation (after Phase 1):
- `hugo --minify --environment production`
- Result: pass (`Pages=204`, `Processed images=372`, no panic).

3. HOLD-route cleanup validation (after Phase 2):
- No wrapper pattern remains in affected routes: `rg "\[\{\{< img-caption" ...` returns no matches.
- No caption attribute remains in affected routes: `rg "caption=\"" ...` returns no matches.
- Production build rerun: `hugo --minify --environment production` passes.

4. Caption entity normalization validation (after Phase 3):
- Route spot-check: `/what-skills-do-i-need-as-a-sfcc-architect/`
- Result: visible figcaption now renders `'blur'` instead of literal `&quot;blur&quot;`.

5. Synthetic video-caption validation (after Phase 4):
- Batch rerun: `validation/ARTICLE-AUDIT-SUMMARY-2026-03-23-RERUN-B9-V3.md`
- Result before video fix: single remaining hold at `/salesforce-b2c-commerce-cloud-22-9-release/` for local-only caption `Watch on YouTube`.
- Expected after video fix: batch 9 rerun no longer reports the synthetic watch-link caption unless explicitly enabled on the shortcode call.

## Scope boundaries

- Phase 1 build-stability fix in shortcode image-processing path.
- HOLD-only caption drift routes in affected batches:
  - Batch 14: 001 through 010.
  - Batch 15: 001, 002, 003, 004, 006, 007, 008, 010.

Excluded:

- Non-caption migration governance, URL policy, canonical policy, or redirect behavior.
- Global replacement of image-processing strategy outside `img-caption`.
